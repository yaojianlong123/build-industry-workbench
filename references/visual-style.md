# Visual direction and design system

## Collect inputs

Accept logos, brand colors, screenshots, websites, products, interior spaces, or plain adjectives. Ask which aspects the user likes or dislikes; a reference is evidence, not a command to copy everything.

If the user has no references, infer suitable directions from audience, environment, device, content density, trust level, and industry tone.

## Present directions

Offer two or three genuinely distinct directions. For each provide:

- a memorable name;
- three to five adjectives;
- why it fits the users and workflow;
- color mood and contrast;
- typography character;
- density, spacing, corner, border, and shadow treatment;
- imagery and icon approach;
- one tradeoff;
- reference characteristics or sourced examples when available.

Recommend one direction instead of remaining neutral.

Example direction families:

- **Reliable utility**: high clarity, restrained color, strong statuses; suited to repair and field service.
- **Editorial portfolio**: generous space, strong imagery, refined typography; suited to photography and creative work.
- **Warm personal care**: calm color, reassuring language, soft components; suited to beauty and wellness.
- **Operational control**: compact density, persistent filters, visible exceptions; suited to logistics and engineering.

Do not lock an industry to a stereotype. Adjust for the user's actual brand and customers.

## Produce the design system

Define a compact token set:

- color roles: canvas, surface, text, muted text, border, primary, success, warning, danger, and focus;
- typography: display, heading, body, label, numeric, size scale, weight, and line height;
- spacing scale, grid, content width, and breakpoints;
- radii, borders, elevation, icons, and motion;
- component rules for buttons, inputs, cards, tables, filters, tabs, badges, dialogs, notifications, and navigation.

Provide concrete values when the target supports them. Check text contrast, keyboard focus, touch targets, zoom, reduced motion, and non-color status cues.

## Reference handling

When external references are used:

- identify the source and access date when practical;
- explain the specific principle being borrowed;
- avoid copying logos, illustrations, branded assets, or a distinctive screen wholesale;
- prefer a small, coherent reference set over a large moodboard;
- note which details are inferred rather than observed.

## Visual deliverables

Depending on available tools, produce one or more of:

- annotated text wireframes;
- a style tile with colors, type, components, and imagery direction;
- a representative high-fidelity core page;
- desktop and mobile variants;
- an implementation-ready token table or CSS-variable mapping;
- a prompt for a UI design or image-generation system.

Always keep the selected visual direction traceable to the approved workflow and hierarchy.
